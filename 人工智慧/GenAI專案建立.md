## GenAI 基本認識

### 比較人工智慧
1. **傳統人工智慧**：專家系統(推理引擎) | 資料標註，分類、預測 | 規則撰寫繁瑣，維護成本高。無法即時更新，符應最新變動。
2. **現代人工智慧**：引入機器學習、深度學習。 | 特徵提取，理解並重構 | 擅長非結構化資料之特徵提取。

### 生成式AI核心
- 學習基礎仰賴大量資料：避免誤差。
- 生成式對抗網路(GAN)：讓兩個神經網路互相競爭，一個生成器創造，一個判別器評估。用於影像重建、資料擴增。


### LLM發展史
- 傳統語言模型的Markov性質，只關注前、後幾個詞。
- 深度學習的遞迴神經網路(RNN)，序列建模的基本框架。
- LSTM：透過「記憶單元」與「門控機制」，用forget gate和output get結構，緩解RNN反向傳播的梯度消失、梯度爆炸問題。
- Transformer：運用多頭注意力機制(multi-head self-attention mechanism)，同時關注序列的每個位置，可併行運算，提取句子不同位置的關聯性，尤其是長距離與語境依賴關係。
- 詞袋模型(bag of words)：計算詞會出現頻度，也搭配 TD-IDF 加權機制，增加關鍵詞掌握度。
- 詞向量模型
    - Word2Vec 最具代表，建立詞彙關聯，包括 CBOW 上下文預測目標詞、Skip-Gram 目標詞預測上下文。
    - GloVe 重視詞彙之間的共現行為。
- 多模態模型(large multimodal models, LMMs)：用模態對齊、語意融合技術，把不同模態建立共同語意空間。
- 大型推理模型(large reasoning models, LRMs)：引入強化學習技術，回答前先將難題拆成多個小步驟，形成思維鏈CoT。

### 模型選用與評估
- 提示工程(prompt engineering)：使用設計過的Prompt，引導AI模型思考方向，有助於精準控制生成結果、提升模型性能。
- 混合專家架構(mixture-of-expert)：將單一任務空間劃分為多個子任務，再由多個專家網路(子模型)分別處理特定的子任務，最終得到整體的預測結果。

- 使用閉源模型
    1. 資料隱私：上傳或請求前，去識別化或加密處理。
    2. 法律合規：是否符合當地法律、國際標準，尤其是對高敏感行業(金融/醫療)。
    3. 效能與穩定性：改成結果快取、批次處理、非同步請求。或與供應商談SLA。改善網路品質。
    4. 成本效益：審查使用模式，量化資源使用樣態，移轉簡易任務給更輕量的模型。
- 使用開源模型 [醫療、金融、公共服務]
    1. 語系支援與領域知識：繁體中文加上特定領域。
    2. 推理效能評估：大模型泛化能力強，小模型輕量。建立客觀評估生成品質。
    3. 開發社群支援：加速模型迭代與修復。
    4. 授權條款：符合使用規範。
    5. 客製化與部署：容器化(Docker/Kunernetes + VLLM/Ollama)、雲端部署、API封裝與整合、模型壓縮、硬體加速(GPU叢集)。
- 模型測試
    - 小型測試資料(golden test dataset)：驗證實際效能時，建立有代表性的測試資料，若為高風險、高複雜度的任務，應把邊界案例(edge case)放入測試中。
    - 基本性能測試(baseline testing)：使用企業內部標註資料，加上Benchmark資料集，在未調參、未微調的狀態下，評估效能，用來比較部署前後的模型表現變化。
    - Benchmark資料集 -> 客觀
    - A/B測試 -> 使用者主觀
    - 手動評估-專家 | 自動化評估-Trinkle Eval | 大模型評估小模型
        - Trinkle Eval 自動化評估
        - Python 套件 HuggingFace Evaluation 提供資料集與評估模組。
        - MLFlow 能搭配自動化測試、版控與跨模型比對。

-  模型表現優化策略
    - 對於不敏感的語言結構、資料類別，用增量學習、少量標註、自訂分詞策略。
    - 對於參數過大壓縮有限的模型，用模型剪枝、量化、知識蒸餾。
    - 對於語系不同，要收集跨語言資料、對齊多語詞彙。
    - 對於邊緣裝置或低度資源場景，要注意記憶體使用情形。

### GenAI MaaS 生成式AI模型即服務 (GenAI model as a Service)
- 定義：將生成式 AI 模型部署到雲端或地端伺服器，提供使用者以 API 或 UI 叫用模型的能力。
- 運作與部署：透過容器化、虛擬化進行封裝，推論引擎接收使用者請求，根據指定參數(提示詞/環境變數/商業規則)回應。也採用熱更新(hot swap)讓新版服務上線。
    - 地端部署大模型要用多個 GPU、分散式架構。
    - 雲端部署要用擴充性佳的虛擬伺服器 + 自動化工具動態配置 CPU 和 GPU。
    - 監控指標：硬體負載比例、記憶體用量、推論延遲、是否閒置。
- GenAI MaaS 架構
    - 資源管理層：動態配置 GPU、TPU，確保高併發、高資料量的效能，監控負載、記錄請求情形。
    - 資料庫/版控系統：儲存模型權重、配置檔、中繼資料(metadata)。
- 長期思考
    - 模型選用：閉源模型供應商更換，閉源切換成開源。
    - 資料傳輸：企業內部資料去識別/加密+最小輸出，建立本地端或私有雲服務。
    - 安全與隱私：驗證身分與存取控。對關鍵欄位用動態遮罩。同態加密。差分隱私。
    - 道德與法律：除了在開發階段資料清洗、標記，也在推論階段加入內容動態檢測、阻擋提示不良訊息。定義對生成內容侵權之責任歸屬。
- 快速部署
    - Ollama (Port: 11434)

## GenAI 分工與任務

### MLOps
- 目標：基於 DevOps 的 CI/CD (應用程式的構建、測試、部署)，把重點放在資料處理、特徵工程、模型維運，機器學習模型的全生命週期。一是為模型建立穩健的生產環境，二是保持系統可擴充性，三是把機器學習的訓練流程自動化。
- 挑戰
    - 版本控制 -> 再現性：模型版本、資料集版本。Git + 資料版本控制。
    - 持續訓練 -> 持續部署：監測指標，自動觸發重新訓練、部署。測試工作包括模型性能測試(依使用場景、資料集)。學習率、批次大小、迭代次數。
    - 資料漂移(data drift)：監測資料分布是否偏移(如 Evidency AI)
    - 模型漂移(model drift)：監測模型的預測能力是否下降。
    - 概念漂移(concept drift)：監測資料關係是否改變
- 工作階段
    1. 資料工程：(1) 資料清洗與標準化，Apache Spark 或 python。(2) 資料集的版本管理，用 DVC。
    2. 特徵工程、模型訓練：特徵提取(圖像的視覺特徵/文本的文字向量)、特徵選擇(除去無效資料)、自動化流程追蹤(AutoML 平台，如Google AutoML、H2O.ai)(參數追蹤，**Kubeflow** Pipelines 或 **MLflow**)。
    3. 模型部署：避免因手動產生部署風險，打包容器映像檔(Docker)再用 Kubernetes 彈性部署。建立可呼叫API，如 FastAPI、Flask、TensorFlow Serving、TorchServe。
    4. 持續監控與再訓練：使用 Promethus、Grafana 監控系統、A/B測試，即時監測資料漂移、模型漂移問題，並結合再訓練。

### LLMOps
- 目標：基於 MLOps 的 CT/CI/CD，運用系統化思維掌握 LLM 整個生命週期，因應模型大規模訓練的巨量運算資源，協助開發者或資料科學家掌握模型狀況、資料品質、運行效率。
- 管理模型：巨量高品質資料取得、模型訓練與微調建立。
- 管理基礎設施：分散式運算與儲存資源整合、自動化管線維護。

- 比 MLOps 更多的挑戰
    - 系統性思考，包括軟硬體管理。
    - 降低使用者操作風險，並注意合法合規、隱私保障。
    - 大型語言模型訓練風險與成本。
    - 從資料源頭嚴格監控
    - 訓練階段：隨持關注每次迭代(epoch)或每一批次(batch)的關鍵參數表現(學習率、損失值、資源使用率)。by TensorBoard。偵測大型叢集環境資源分配與使用，加快訓練頻度。

## 檢索增強生成 (RAG)

### 比較 RAG 與 fine-tuning
- RAG：用檢索機制 | 更新知識庫 | 檢索策略與資料庫內容 | 動態擴充(頻繁更新)
    - 定期自動化更新/檢視外部文件庫
    - 挑選正確 embedding 模型處理專業術語
- 微調：要資料標註 | 更新模型 | 形塑風格與專業度 | 專業深度(精準匹配) 
    - 注意資料標註的品質(人工校正)
    - 擬定迭代與驗證機制(反覆測試)，定期再訓練 
    - 專業詞彙的保留
- 混合策略
    - 微調訓練資料：教科書、學習筆記、教案
    - RAG 外部資料：動態擴充資料

### 詞嵌入向量 (word embedding)
- 詞嵌入：把自然語言轉換成數學向量，放置空間即為詞向量。
    - embedding：以一種可被演算法理解操作方式，把資料中的抽象概念映射到向量空間，尤其是高維、稀疏、難以直接量化的資料。
    - embedding vector 特性
        - 透過學習與壓縮，能以低維度向量表示。
        - 語意相似度能反映在空間相進度。
        - 高效性、可解釋性有助於機器學習和深度學習。
    - 衡量距離的方法 -> Top-K 的 K 值
        - 歐幾里得距離(Euclidean distance)：差值平方和
        - 餘弦相似度(cosine similarity)：向量夾角
        - 內積(dot product)
        - 曼哈頓距離(Manhatta distance)：每個維度絕對差值的累計
    - 維度降低的方法
        - 主成分分析(PCA)：找出資料中方差最大的方向，並把它們定義成新的座標軸。
        - 奇異值分解(SVD)：將矩陣拆分成多個正交向量與對角矩陣的乘積。
    - 評估嵌入效果
        - 平均倒數排名(MRR)
        - MAP
        - NDCG

### 建置 RAG 知識庫
1. chunking
    - 目的：把文本段落分割成可讀裡處理的字串，或抽取詞組、短語，降低亂度值。
    - chunking 作法
        1. 固定長度切塊：易於估算資源需求。| 也能以句號或段落分割
        2. 語意密度切塊：耗用時間資源較長。(複雜議題、多重觀點) | 以句法樹、章節、模型查找，以嵌入向量相似度高的，放在同一個切塊
        3. 混合式切塊：1+2互補。|以固定長度大略切割，再輔以語意細切
        4. 分層切塊：大型知識庫建置。| 按照章節/主題、子章節/子主題，逐層切塊

        > 最佳分割問題：在達到高語意一致性、高可讀性的前提，維持模型效能與系統資源的平衡。<br>
        > - 動態規劃(dynamic programming)：問題笧結成子問題，由下而上累積最佳解。-> 精確度
        > - 貪婪演算法(greedy algorithm)：考量運算效率，快速取得局部最佳解。-> 速度

        > 檢索模組的索引架構
        > 1. 倒排索引(inverted index)：根據k-mean最相近的關鍵字分群，排除非相關文本分群。
        > 2. 向量索引(vector index)：捕捉文本在高維度空間的語意相似度。

    - chunking 挑戰
        1. 顆粒度，太大將造成關鍵詞與語意失配(特徵稀疏)，太小則納入過多無用資訊到運算(語意斷裂)。
        2. 共享重複片度，讓檢索和深度分析感知到兩段的連續性。
        3. 跨語言夾雜的文本，要分根據語種分開分塊，妥善處理邊界。
        4. 特殊文本(程式碼、數學公式)的語法結構，應保持整段完整。
        5. 段落分明有層次文本，分章節、分主題存入。
         
2. 中繼資料(metadata)
    - 當作資料檢索時，除了提供來源識別，也能用文件屬性(建檔日/檔案格式/作者/部門標籤)聚焦搜索範圍。
    - 管理操作紀錄、更新日期、修改次數。
    - 避免過多匹配(相似語意)，或者重要資料缺失(未保留層級結構、特定格式)。
    - 混合策略：同時評估檢索與文件兩者的語意近似度。
    - 把中繼資料納入提示詞模板，解析實際使用情境。

3. 知識資料庫 = 向量資料庫(vector db)
    - 如何部署？
        - 地端 ChromaDB：向量化+語意比對，資料可擴充性、API工具
        - 雲端 Google、AWS、Azure
    - 資料管線
        - 資料蒐集與前處理 -> 文本分割 -> 語意向量嵌入 & 高效索引建置 -> 提示詞設計 -> 模型產生 -> 知識庫持續更新
        - 高併發的檢索/生成機制：(1) 把向量索檢索系統部署到多個節點，允許多個用戶同時查詢。(2) 把語言模型服務設計成多執行緒、非同步呼叫。(3) 快取機制(向量比對/Hash判定)，直接回傳。(4) 答案顯示採用串流。
        - 上下文增強(context augmentation)：把從向量檢索取得的知識片段，作為生成回答的依據。
        
    - 如何最適化？
        - 提高檢索效率：量化、加速演算法、硬體優化、快取層設計
        - 提升檢索準確性：移除不良文件、重新嵌入、依使用者需求(半)自動調整中繼資料欄位
        - 監控性能：硬體負載、索引設計
        - 降低模型溫度(0.05 ~ 0.30)：降低隨機性
        - 限制最大生成長度：避免資源耗用
        - 帶入資料引用來源
        - 收集使用者對答案的滿意度、正確性
        - 透過微調適應開卷作答，減少幻覺

### 優化 RAG 知識庫
- 常見的優化方向
    - 文本事先整理：初期建立資料流水線，把不同樣式文本先資料清洗、格式統一，再依據文本種類設計索引，並自動化後續的向量化。
    - 訊息過載避免：使用 NLP 模型預先偵測主題、實體名稱、關鍵字。
    - 動態切塊策略：用固定大小的視窗滑動，在文本切塊時保留上下文連續性。
    - 快取快答機制：避免重複問答。
    - API 分層查詢：用嵌入模型快速篩選相關性，只保留最可能結果進到更深層的 LLM 生成。
    - 大小模型分工：必要時切換到大模型推論。
    - 提示工程最佳化：減少 token 數仍維持回應的品質和精度。

- 優化檢索方法
    - 句子窗口檢索：切細斷句直接向量化 | 快速問答、短文本
    - 自動合併檢索：切細文本+動態合併斷句(演算法)+向量化 | 大型文本、脈絡連貫
    - 相關片段提取：段落向量化、查詢向量化、相似度排序(動態加權或用多模型的集成學習) | 專題研究、新聞報導

- 知識圖譜(knowledge graph)
    - 提供生成式 AI 模型更清晰的背景知識、多層次語意訊息，降低幻覺。
    - 常見於搜尋引擎、推薦系統、問答系統。
    - 法條的連結性、技術手冊的多領域性
    - KAG (knowledge-awareness graph)：如撰寫時參考文獻，知道哪些資訊要引用
        - 直接被整合到AI訓練，協助模型沿著圖中的不同實體關聯，更精準的檢索與推理。
        - 支援關鍵詞、概念、語意檢索，快速擷取並定位使用者輸入的關鍵詞。
        - 清楚得知推理過程，確保生成內容的合規性、可追溯性。
        - 挑戰 1：持續更新的成本不小
        - 挑戰 2：研究圖嵌入技術、檢索策略
    - GraphRAG：如大腦先構築一個概念地圖，根據地圖進行推論
        - 不只依賴關鍵字比對與向量檢索，也同時考量知識圖譜產出的關連與概念。
        - 第一步、圖形檢索：系統查詢意圖與問題，找出圖譜中最符合的節點(=知識實體)或上下文。
        - 第二步、生成整合：充分考量知識圖譜本身，以及查詢意圖，最終在回應中納入更深層語意。
        - 挑戰 1：設計高效的索引結構或分散式圖譜之運算方案，降低查詢、圖形擴散。
        - 挑戰 2：對圖譜資料進行清洗、正規化，並採用注意力機制、專家審核，確保邏輯、語意的一致性。
